# Data copy chain — transport layer (status-go → client)

Copies of one response/signal between status-go producing a Go struct and the Nim side holding a
JsonNode. SG = vendor/status-go, M = mobile.

**Headline:** RPC response: desktop 6–7 copies, Android 13–14. Signal: desktop 6, Android ~14, plus two
full `org.json` parses of every signal in the Android service process.

## RPC, Go side (both platforms)
1. geth `json.Marshal(result)` into a RawMessage — go-ethereum@v1.16.3/rpc/json.go:116-121
2. envelope marshalled again; the RawMessage is re-scanned and copied — SG/pkg/backend/node/rpc/rpc.go:50
3. `string(data)` — rpc.go:55
4. `C.CString` — SG/build/bin/statusgo-lib/main.go:16,20 (generated by tools/generate-cbindings); freed via `Free` (:441)

## RPC, desktop Nim
- `$funcOut` copy — src/status_go.nim:74-82; `Json.decode` builds a JsonNode tree — src/backend/core.nim:36

## RPC, Android
- Service process: `NewStringUTF` (1–2×) — M/statusgo_service/statusgo_service_jni.cpp:147; `getBytes` —
  StatusGoService.java:542; <64KB inline `byte[]` (RpcResponse.java:94) else copied into ashmem
  (StatusGoService.java:547-560).
- UI process: inline `byte[]` + `new String` (RpcResponse.java:111,56) or 2× CharBuffer + `toString`
  (RpcResponse.java:65); `GetStringUTFChars` — M/statusgo_stub/statusgo_stub.cpp:102; `dupToMalloc`
  — :103; then the Nim steps.

## Binder 1MB limit
- Responses protected: ≥64KB go through shared memory (StatusGoService.java:54-60).
- Signals protected at ≥128KB; smaller go inline as UTF-16 one-way calls (:52, 212-228); a failed
  delivery is only logged → **signal silently dropped** (:231-240).
- **Requests are not protected**: always inline UTF-16 (IStatusGoService.aidl:15); a
  `TransactionTooLargeException` is treated as any binder failure and calls `requestFrontendRestart`
  (StatusGoServiceClient.java:339-371, :368). No chunking.

## Signals, Go side
1. envelope `json.Marshal` — SG/internal/signal/signals.go:51; 2. `string(data)` + `C.CString` —
   :63; 3. callback runs synchronously on the Go thread, C copy freed after (:64-65; signals.c:13-17).

## Signals, desktop receive
1. `QString::fromUtf8` (UTF-16, 2×) — ui/StatusQ/src/externc.cpp:278-281; 2. slot converts back to
   UTF-8 then to a Nim string — signals_manager.nim:67; 3. `parseJson` — :45.

## Signals, Android
- Service process: `NewStringUTF` while holding a lock, synchronously on the Go thread
  (jni.cpp:35-46); `getBytes` 2–3× only to measure size (StatusGoService.java:191, 210, 214); full
  JSON parse to detect `node.login` (:309-328); full JSON parse for notifications before the
  "UI visible" check (StatusNotificationManager.java:91-95); ≥128KB: one shared-memory copy **per
  listener inside the loop** (:224, 281), else `writeString` UTF-16.
- UI process: Java String or CharBuffer+String (StatusGoServiceClient.java:69, 89); `getBytes` to
  measure (:71, 91); `GetStringUTFChars` (statusgo_stub.cpp:152); then the desktop steps.

## Side bug
The service-side argument parser turns any `\uXXXX` escape into `'?'` (jni.cpp:69-74) while the stub
writes raw control characters as `\u00XX` (statusgo_stub.cpp:58-61), so those characters reach
status-go as `'?'`.

## Easy cuts
1. Substring-scan the signal type instead of the two service-side JSON parses.
2. Compute UTF-8 bytes once and create the shared-memory region once, outside the listener loop.
3. Pass byte arrays/buffers through JNI instead of Java Strings.
4. Give requests a shared-memory path, or handle `TransactionTooLargeException` without restarting
   the frontend.
